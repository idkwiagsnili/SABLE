# 1. 키 분배 문제

대칭 키 암호는 암호화와 복호화에 같은 키를 사용한다.

```text
평문 + 비밀 키 → 암호문
암호문 + 같은 비밀 키 → 평문
```

따라서 통신을 시작하기 전에 송신자와 수신자가 같은 비밀 키를 가지고 있어야 한다.

하지만 비밀 키를 인터넷으로 그대로 전송하면 공격자가 중간에서 키를 가로챌 수 있다.

```text
Alice → Bob : 비밀 키 전송
        Eve : 비밀 키 탈취
```

공격자가 비밀 키를 얻으면 암호화 알고리즘이 강하더라도 암호문을 복호화할 수 있다.

이처럼 **암호화에 사용할 비밀 키를 상대방에게 어떻게 안전하게 전달할 것인가**를 키 분배 문제라고 한다.

### 사용자가 많아지면 발생하는 문제

모든 사용자가 서로 다른 대칭 키를 사용한다고 가정하면 필요한 키의 개수가 빠르게 증가한다.

```text
사용자 2명 : 키 1개
사용자 3명 : 키 3개
사용자 4명 : 키 6개
사용자 10명 : 키 45개
```

사용자가 `n`명일 때 필요한 대칭 키의 개수는 다음과 같다.

```text
n × (n - 1) / 2
```

따라서 대칭 키 암호는 빠르다는 장점이 있지만, 사용자가 많아질수록 키를 전달하고 관리하기 어려워진다.

# 2. 공개 키·대칭 키란?

## 2-1. 대칭 키

대칭 키 암호는 하나의 비밀 키를 암호화와 복호화에 함께 사용하는 방식이다.

```text
암호화 키 = 복호화 키
```

예를 들어 Alice와 Bob이 같은 대칭 키를 공유하고 있다면 Alice는 그 키로 데이터를 암호화하고, Bob은 같은 키로 데이터를 복호화한다.

## 대칭 키의 특징

- 암호화와 복호화 속도가 빠르다.
- 큰 파일이나 많은 데이터를 처리하기에 적합하다.
- 통신하는 두 사람이 같은 키를 가지고 있어야 한다.
- 키가 유출되면 공격자도 데이터를 복호화할 수 있다.
- 키를 상대방에게 안전하게 전달해야 한다.

### 대표적인 대칭 키 알고리즘

- AES
- ChaCha20

---

## 2-2. 공개 키

공개 키 암호는 서로 다른 두 개의 키를 사용하는 방식이다.

```text
공개 키 : 다른 사람에게 공개할 수 있는 키
개인 키 : 소유자만 비밀로 보관하는 키
```

공개 키와 개인 키는 서로 연결되어 있지만 공개 키만 가지고 개인 키를 알아내기는 매우 어렵다.

RSA와 같은 공개 키 암호에서는 공개 키로 암호화한 값을 대응되는 개인 키로 복호화할 수 있다.

```text
공개 키로 암호화 → 개인 키로 복호화
```

전자서명에서는 반대로 개인 키로 서명하고 공개 키로 서명이 올바른지 검증한다.

```text
개인 키로 서명 → 공개 키로 검증
```

## 공개 키의 특징

- 공개 키는 다른 사람에게 공개할 수 있다.
- 개인 키를 직접 전달할 필요가 없다.
- 안전한 통신을 시작하는 데 사용할 수 있다.
- 인증과 전자서명에 사용할 수 있다.
- 대칭 키 암호보다 계산이 복잡하고 속도가 느리다.

공개 키가 공개되어 있다고 해서 아무 공개 키나 믿어도 되는 것은 아니다.

공격자가 자신의 공개 키를 정상적인 사용자의 공개 키인 것처럼 전달할 수 있기 때문에 실제 통신에서는 인증서를 이용해 공개 키의 주인을 확인한다.

# 3. 공개 키·대칭 키의 역할

공개 키와 대칭 키는 서로 경쟁하는 암호 방식이 아니다.

실제 통신에서는 각 방식의 장점을 함께 사용한다.

| 구분 | 공개 키 | 대칭 키 |
|---|---|---|
| 사용하는 키 | 공개 키와 개인 키 | 하나의 비밀 키 |
| 처리 속도 | 비교적 느림 | 빠름 |
| 주된 역할 | 키 설정, 인증, 전자서명 | 실제 데이터 암호화 |
| 장점 | 비밀 키를 직접 보내지 않아도 됨 | 많은 데이터를 빠르게 처리함 |
| 단점 | 많은 데이터를 처리하기에는 비효율적 | 키를 안전하게 공유해야 함 |

## 공개 키의 역할

공개 키 암호는 통신을 시작할 때 상대방을 확인하고 대칭 키를 안전하게 설정하는 역할을 한다.

```text
공개 키의 역할
1. 상대방 인증
2. 대칭 키 설정
3. 전자서명 생성과 검증
```

## 대칭 키의 역할

대칭 키 암호는 연결이 설정된 이후 실제 데이터를 빠르게 암호화하는 역할을 한다.

```text
대칭 키의 역할
1. 메시지 암호화
2. 파일 암호화
3. 실제 통신 데이터 보호
```

## 두 암호 방식을 함께 사용하는 흐름

```text
1. 서버가 공개 키와 인증서를 전달한다.

2. 사용자는 인증서를 확인하여
   공개 키가 실제 서버의 것인지 검사한다.

3. 공개 키 암호 방식을 이용하여
   통신에 사용할 대칭 키를 안전하게 설정한다.

4. 설정된 대칭 키로
   실제 데이터를 빠르게 암호화한다.

5. 통신이 끝나면 사용한 대칭 키를 폐기한다.
```

HTTPS와 같은 실제 통신에서도 공개 키 암호를 이용해 안전한 연결을 시작하고, 이후의 실제 데이터는 AES나 ChaCha20과 같은 대칭 키 암호로 처리한다.

```text
키 분배 문제
= 같은 비밀 키를 상대방과 안전하게 공유해야 하는 문제

공개 키
= 안전한 통신 시작, 인증, 대칭 키 설정을 담당

대칭 키
= 연결 이후의 실제 데이터를 빠르게 암호화
```
