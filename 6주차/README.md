## 1. 블록 단위 암호화

### 정의

블록 단위 암호화는 평문을 정해진 크기의 블록으로 나누어 암호화하는 방식이다.

대표적인 블록 암호인 AES는 128비트, 즉 16바이트 단위로 데이터를 처리한다.

긴 데이터는 한 블록으로 끝나지 않기 때문에 여러 블록을 어떤 방식으로 암호화할지 정해야 한다.
이때 사용하는 방식이 ECB, CBC, CTR 같은 운영 모드이다.

### 특징

* 데이터를 한 글자씩 처리하는 것이 아니라 정해진 크기의 덩어리로 처리한다.
* 같은 블록 암호를 사용해도 운영 모드에 따라 암호문이 달라진다.
* 운영 모드에 따라 보안성, 속도, IV 사용 방식이 달라진다.

### 예시

평문이 다음과 같다고 가정한다.

```text
ABCDABCDABCDABCD
```

블록 크기가 4바이트라면 다음처럼 나눌 수 있다.

```text
[ABCD] [ABCD] [ABCD] [ABCD]
```

여기서 같은 블록이 반복되기 때문에 운영 모드를 잘못 사용하면 반복 패턴이 암호문에도 드러날 수 있다.

---

## 2. ECB 모드

### 정의

ECB는 Electronic Codebook의 약자이다.

각 평문 블록을 서로 독립적으로 암호화하는 가장 단순한 방식이다.

```text
C1 = E(K, P1)
C2 = E(K, P2)
C3 = E(K, P3)
```

여기서 P는 평문 블록, C는 암호문 블록, K는 키를 의미한다.

### 특징

* 구조가 단순하다.
* 각 블록을 따로 암호화하기 때문에 병렬 처리가 가능하다.
* 하지만 같은 평문 블록은 항상 같은 암호문 블록으로 바뀐다.

### 문제점

ECB는 같은 내용이 반복되면 암호문에서도 반복되는 패턴이 남을 수 있다.

예를 들어 평문 블록이 다음과 같다면,

```text
[ABCD] [ABCD] [ABCD]
```

ECB에서는 암호문도 다음처럼 같은 형태가 반복될 수 있다.

```text
[X1] [X1] [X1]
```

그래서 ECB는 실제 데이터 암호화에 사용하기에는 안전하지 않다.

## 3. CBC 모드

### 정의

CBC는 Cipher Block Chaining의 약자이다.

현재 평문 블록을 바로 암호화하지 않고, 이전 암호문 블록과 XOR한 뒤 암호화한다.

```text
C1 = E(K, P1 XOR IV)
C2 = E(K, P2 XOR C1)
C3 = E(K, P3 XOR C2)
```

첫 번째 블록은 이전 암호문이 없기 때문에 IV를 사용한다.

### 특징

* 이전 암호문 블록이 다음 블록에 영향을 준다.
* 같은 평문 블록이 반복되어도 암호문이 똑같이 반복되지 않는다.
* 첫 번째 블록을 위해 IV가 필요하다.

### 예시

ECB에서는 같은 평문 블록이 반복되면 같은 암호문이 나올 수 있다.

하지만 CBC에서는 이전 암호문이 다음 블록에 섞이기 때문에 같은 평문 블록이어도 다른 암호문이 나올 수 있다.

즉, CBC는 ECB보다 반복 패턴을 숨기는 데 유리하다.

---

## 4. CTR 모드

### 정의

CTR은 Counter의 약자이다.

평문을 직접 블록 암호에 넣는 것이 아니라, nonce와 counter 값을 암호화해서 키스트림을 만들고 그 값을 평문과 XOR한다.

```text
S1 = E(K, Nonce || Counter1)
C1 = P1 XOR S1

S2 = E(K, Nonce || Counter2)
C2 = P2 XOR S2
```

### 특징

* 블록 암호를 스트림 암호처럼 사용할 수 있다.
* 암호화와 복호화가 같은 XOR 구조로 동작한다.
* 블록끼리 의존성이 적어서 병렬 처리가 가능하다.
* nonce와 counter 값을 절대 재사용하면 안 된다.

### 문제점

CTR에서는 같은 키와 같은 nonce/counter를 다시 사용하면 같은 키스트림이 만들어진다.

이 경우 공격자가 두 암호문을 비교해서 평문 정보를 추측할 수 있다.

그래서 CTR에서는 nonce/counter 관리가 매우 중요하다.

---

## 5. IV의 필요성

### IV란?

IV는 Initialization Vector의 약자이고, 초기화 벡터라고 한다.

암호화를 시작할 때 사용하는 초기값이다.

### 필요한 이유

IV는 같은 평문을 같은 키로 암호화하더라도 매번 다른 암호문이 나오도록 돕는다.

만약 IV가 없다면 같은 평문과 같은 키를 사용할 때 항상 같은 암호문이 나올 수 있다.

그러면 공격자는 내용을 몰라도 같은 메시지가 반복되었다는 사실을 알 수 있다.

### 주의할 점

* IV는 비밀키처럼 반드시 숨겨야 하는 값은 아니다.
* 하지만 같은 키에서 같은 IV를 반복해서 사용하면 안 된다.
* CBC에서는 첫 번째 블록의 패턴을 숨기기 위해 IV가 필요하다.
* CTR에서는 nonce/counter가 키스트림을 결정하므로 재사용하면 매우 위험하다.
