## 1. 대칭키 암호란?

대칭키 암호는 **암호화와 복호화에 같은 키를 사용하는 암호 방식**이다.

```text
평문 + 비밀키 = 암호문
암호문 + 같은 비밀키 = 평문
```

즉, 데이터를 잠글 때 사용한 키와 다시 열 때 사용하는 키가 같다.  
그래서 대칭키 암호에서는 **키 관리**가 가장 중요하다.

키가 외부로 유출되면 공격자도 같은 키로 암호문을 복호화할 수 있다.

---

## 2. 대칭키 암호의 암호화

암호화는 사람이 읽을 수 있는 **평문**을 알아보기 어려운 **암호문**으로 바꾸는 과정이다.

```text
Plaintext + Key -> Ciphertext
```

암호화의 목적은 중간에 누군가 데이터를 가로채도 내용을 알 수 없게 만드는 것이다.

---

## 3. 대칭키 암호의 복호화

복호화는 암호문을 다시 원래 평문으로 되돌리는 과정이다.

```text
Ciphertext + Same Key -> Plaintext
```

대칭키 암호에서는 암호화에 사용한 키와 같은 키를 사용해야 정상적으로 복호화된다.

---

## 4. 대칭키 암호의 종류

대칭키 암호는 크게 **블록 암호**와 **스트림 암호**로 나눌 수 있다.

### 4-1. 블록 암호

블록 암호는 데이터를 일정한 크기의 블록으로 나누어 암호화하는 방식이다.

대표적인 예시는 **AES**가 있다.  
AES는 파일 암호화, 디스크 암호화, 네트워크 통신 등에서 많이 사용된다.

```text
평문 데이터 -> 블록 단위로 분리 -> 각 블록 암호화
```

---

### 4-2. 스트림 암호

스트림 암호는 데이터를 비트나 바이트 단위로 연속해서 암호화하는 방식이다.

대표적인 예시는 **ChaCha20**이 있다.

스트림 암호는 비밀키를 이용해 암호화에 사용할 임시 값인 키스트림을 만든다.  
그리고 평문과 키스트림을 XOR 연산해서 암호문을 만든다.

```text
평문 XOR 키스트림 = 암호문
암호문 XOR 같은 키스트림 = 평문
```

---

## 5. 대칭키 암호의 속도

대칭키 암호는 일반적으로 공개키 암호보다 빠르다.

대칭키 암호는 XOR, 치환, 순열, 비트 연산처럼 컴퓨터가 빠르게 처리할 수 있는 연산을 많이 사용한다.

반면 공개키 암호는 큰 수 연산이나 타원곡선 연산처럼 복잡한 계산을 사용하기 때문에 상대적으로 느리다.

```text
대칭키 암호: 빠름, 대용량 데이터 암호화에 적합
공개키 암호: 느림, 키 교환이나 인증에 적합
```

---

## 6. 대칭키 암호의 키 공유 문제

대칭키 암호의 가장 큰 단점은 **키 공유 문제**다.

통신하는 양쪽이 같은 키를 가져야 하므로, 처음에 키를 안전하게 전달하는 과정이 필요하다.

```text
A -> B : 비밀키 전송
공격자 : 중간에서 비밀키 탈취
결과 : 공격자도 암호문 복호화 가능
```

키 공유 문제를 해결하기 위해 다음과 같은 방법이 사용된다.

- 직접 만나서 키를 전달한다.
- 공개키 암호로 대칭키를 암호화해서 전달한다.
- Diffie-Hellman 같은 키 교환 방식을 사용한다.
- 세션마다 새로운 키를 사용한다.

대칭키 암호는 **속도가 빠르지만 키 공유와 키 관리가 어렵다**는 특징이 있다.
