## 1. 전자서명이란?

전자서명은 디지털 환경에서 이 데이터가 누가 만든 것인지 확인하고, 중간에 바뀌지 않았는지 검증하는 기술이다.

현실에서 종이 계약서에 서명을 하면 작성자를 확인할 수 있다.

전자서명도 비슷하게 디지털 문서나 메시지에 서명을 남긴다.

```
종이 문서 + 손글씨 서명 = 작성자 확인
디지털 문서 + 전자서명 = 작성자 확인 + 변조 확인
```

전자서명은 단순히 이름을 적는 것이 아니라 개인키와 공개키를 이용해서 만든다.

개인키는 서명할 때 사용하고, 공개키는 서명이 올바른지 확인할 때 사용한다.

```
개인키 : 서명 생성
공개키 : 서명 검증
```

즉, 전자서명은 암호화처럼 내용을 숨기는 기술이라기보다는 누가 만들었는지와 바뀌지 않았는지를 확인하는 기술이다.

---

## 2. 무결성과 인증

전자서명을 이해하려면 먼저 무결성과 인증을 알아야 한다.

무결성은 데이터가 중간에 바뀌지 않았다는 의미이다.

인증은 그 데이터를 만든 사람이 누구인지 확인하는 것이다.

```
무결성 : 데이터가 변조되지 않았는가?
인증 : 누가 만든 데이터인가?
```

예를 들어 Alice가 Bob에게 파일을 보냈다고 가정한다.

```
Alice -> Bob : report.txt
```

Bob은 이 파일을 받았을 때 두 가지가 궁금하다.

```
1. 파일 내용이 중간에 바뀌지 않았는가?
2. 이 파일이 정말 Alice가 보낸 것인가?
```

첫 번째는 무결성 문제이고, 두 번째는 인증 문제이다.

전자서명은 이 두 가지를 함께 확인할 수 있게 해준다.

---

## 3. 해시 함수와 무결성

해시 함수는 데이터를 고정된 길이의 값으로 바꾸는 함수이다.

```
message -> hash(message)
```

해시값은 데이터의 지문처럼 사용할 수 있다.

데이터가 조금만 바뀌어도 해시값은 완전히 달라진다.

예를 들어 다음과 같은 메시지가 있다고 가정한다.

```
message1 = "pay 10000 won"
message2 = "pay 90000 won"
```

두 문장은 숫자 하나만 다르지만 해시값은 서로 다르게 나온다.

```
hash(message1) = A1B2...
hash(message2) = C9D7...
```

그래서 파일을 받은 뒤 다시 해시를 계산하면 데이터가 바뀌었는지 확인할 수 있다.

```
받은 파일의 해시 == 원래 해시
-> 파일이 바뀌지 않았다고 판단
```

하지만 해시만으로는 부족하다.

공격자가 파일을 바꾼 다음, 바뀐 파일의 해시도 새로 계산해서 같이 보내면 받는 사람은 누가 만든 파일인지 알 수 없다.

```
공격자 -> Bob : fake_file, hash(fake_file)
```

즉, 해시는 무결성 확인에는 도움이 되지만 인증까지 해결하지는 못한다.

## 4. 비밀번호 해시와 salt

해시는 비밀번호 저장에도 사용된다.

서버가 사용자의 비밀번호를 그대로 저장하면 위험하다.

```
user : alice
password : 123456
```

데이터베이스가 유출되면 비밀번호가 그대로 노출된다.

그래서 서버는 비밀번호 원문을 저장하지 않고 해시값을 저장한다.

```
stored_hash = hash(password)
```

로그인할 때는 사용자가 입력한 비밀번호를 다시 해시해서 저장된 값과 비교한다.

```
hash(input_password) == stored_hash
-> 로그인 성공
```

하지만 단순히 해시만 사용하는 것도 안전하지 않다.

같은 비밀번호는 항상 같은 해시값을 만들기 때문이다.

```
hash("123456") = AAAA
hash("123456") = AAAA
```

여러 사용자가 같은 비밀번호를 사용하면 같은 해시값이 저장된다.

이 문제를 줄이기 위해 사용하는 것이 salt이다.

salt는 비밀번호에 추가하는 랜덤 값이다.

```
hash(password + salt)
```

예를 들어 Alice와 Bob이 같은 비밀번호를 사용한다고 하자.

```
Alice password = 123456
Alice salt = A1

Bob password = 123456
Bob salt = B7
```

같은 비밀번호라도 salt가 다르면 해시값도 달라진다.

```
hash(123456 + A1) = XX11
hash(123456 + B7) = YY22
```

salt를 사용하면 같은 비밀번호를 사용하더라도 저장되는 해시값이 달라진다.

### salt의 특징

* 사용자마다 다른 값을 사용한다.
* 같은 비밀번호라도 다른 해시값이 나오게 한다.
* 미리 계산된 해시 목록을 이용한 공격을 어렵게 만든다.
* salt는 비밀번호처럼 반드시 숨겨야 하는 값은 아니다.

다만 salt를 사용한다고 해서 약한 비밀번호가 안전해지는 것은 아니다.

공격자가 데이터베이스를 얻으면 salt와 hash를 가지고 계속 비밀번호를 대입해볼 수 있다.

그래서 실제 비밀번호 저장에는 SHA-256 같은 빠른 해시만 사용하는 것이 아니라 bcrypt, scrypt, Argon2 같은 느리게 계산되도록 설계된 방식을 사용한다.

## 5. 해시와 전자서명의 연결

전자서명은 보통 메시지 전체에 바로 서명하지 않는다.

먼저 메시지를 해시한 뒤, 그 해시값에 서명한다.

```
message -> hash(message) -> sign
```

이렇게 하는 이유는 메시지 전체가 클 수 있기 때문이다.

긴 문서나 큰 파일 전체에 직접 서명하는 것보다, 고정된 길이의 해시값에 서명하는 것이 효율적이다.

전자서명의 흐름은 다음과 같다.

```
1. 메시지를 해시한다.
2. 해시값에 개인키로 서명한다.
3. 메시지와 서명을 함께 보낸다.
4. 받는 사람은 공개키로 서명을 검증한다.
```

예를 들어 Alice가 Bob에게 파일을 보낸다고 하면 다음과 같다.

```
Alice:
h = hash(file)
signature = sign(private_key, h)

Alice -> Bob:
file, signature

Bob:
h = hash(file)
verify(public_key, h, signature)
```

검증에 성공하면 Bob은 파일이 중간에 바뀌지 않았고, Alice의 개인키로 서명된 파일이라는 것을 알 수 있다.

## 6. 전자서명과 암호화의 차이

전자서명과 암호화는 공개키와 개인키를 사용한다는 점에서 비슷해 보일 수 있다.

하지만 목적이 다르다.

암호화의 목적은 내용을 숨기는 것이다.

```
공개키로 암호화
개인키로 복호화
```

전자서명의 목적은 누가 만들었는지 확인하는 것이다.

```
개인키로 서명
공개키로 검증
```

정리하면 다음과 같다.

```
암호화
= 내용을 숨기기 위한 것

전자서명
= 작성자와 변조 여부를 확인하기 위한 것
```

따라서 전자서명을 했다고 해서 메시지 내용이 숨겨지는 것은 아니다.

내용을 숨기고 싶다면 암호화를 따로 사용해야 한다.

## 7. 전자서명의 확인 요소와 한계

전자서명을 사용하면 다음을 확인할 수 있다.

```
1. 데이터가 중간에 바뀌지 않았는가?
2. 해당 개인키를 가진 사람이 서명했는가?
3. 나중에 서명자가 서명 사실을 부인하기 어려운가?
```

첫 번째는 무결성이다.

두 번째는 인증이다.

세 번째는 부인 방지이다.

부인 방지는 나중에 서명자가 “내가 서명한 것이 아니다”라고 말하기 어렵게 만드는 성질이다.

왜냐하면 개인키는 서명자만 가지고 있어야 하기 때문이다.

```
개인키로 서명 가능
공개키로 누구나 검증 가능
```

이 구조 때문에 전자서명은 계약서, 인증서, 소프트웨어 업데이트, 블록체인 거래 등에서 사용된다.

하지만 전자서명도 모든 것을 해결하지는 못한다.

첫 번째로 개인키가 유출되면 위험하다.

```
개인키 유출
-> 공격자가 대신 서명 가능
```

두 번째로 공개키가 진짜 누구의 것인지 확인해야 한다.

공격자가 자신의 공개키를 Alice의 공개키인 것처럼 속이면, Bob은 잘못된 서명을 믿을 수 있다.

```
Eve 공개키 -> Alice 공개키인 것처럼 전달
Bob -> 잘못된 공개키로 검증
```

그래서 실제 인터넷 환경에서는 인증서를 사용한다.

인증서는 공개키가 누구의 것인지 확인해주는 역할을 한다.

HTTPS에서도 서버가 자신의 공개키와 인증서를 보내고, 브라우저는 인증서를 확인한 뒤 서버를 신뢰한다.

## 핵심 정리

```
해시
= 데이터의 지문을 만드는 방식

salt
= 같은 비밀번호라도 다른 해시값이 나오도록 추가하는 랜덤 값

비밀번호 해시
= 비밀번호 원문을 저장하지 않기 위한 방식

무결성
= 데이터가 중간에 바뀌지 않았는지 확인하는 것

인증
= 데이터를 만든 주체가 누구인지 확인하는 것

전자서명
= 개인키로 서명하고 공개키로 검증하는 방식
```

전자서명은 데이터를 숨기는 기술이 아니다.

전자서명은 데이터가 바뀌지 않았는지 확인하고, 누가 서명했는지 검증하기 위한 기술이다.

따라서 전자서명은 무결성, 인증, 부인 방지를 제공한다.

---

## 한 줄 요약

전자서명은 개인키로 만든 디지털 도장을 공개키로 확인해서 데이터의 작성자와 변조 여부를 검증하는 기술이다.
